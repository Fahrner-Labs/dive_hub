# Check escapes

`pnpm check` runs only what changed, and in one ui-quality variant ([ADR 0023](../decisions/0023-faster-checks.md),
amendments of 2026-10-24); CI's `pnpm check:full` on the pull request is the gate. This log counts what slipped past
the local check, so its certainty can be measured and the path map widened where it is wrong. It also records a
local check incident that wrote outside the sandbox it was meant to stay in, so the same escape is not repeated.

**Who writes an entry:** whoever pushed the branch and sees its CI fail (the agent session that opened the pull
request, or the owner), when every commit on it had a green local `pnpm check`; or whoever sees the local check
write outside its sandbox. CI's job summary names the failed browser tests ("Failed browser tests") and the tests
that passed only on a retry ("Flaky browser tests"). A failure that is a flaky test also counts; say so. A test that
passed on its retry does not fail the run, so it needs no entry here; the job summary counts it.

**Format:** one line per escape, newest first:
`- YYYY-MM-DD, PR #n, <commit sha7>: <failed spec or step> — <cause: map gap / variant / flaky / other> — <fix>`

- 2026-11-10, PR #49, 3f6e04a: gone-dives.spec.ts:56 ("Delete here too" after Cancel) and the server-test step (a pooled client's "terminating connection due to administrator command" after all 1691 tests passed) — other, not flaky: the pre-commit hook ran `pnpm check` on the working tree but committed the earlier staged version of the file, so the check never saw the version that was pushed; the server step's non-zero exit was the pool error during teardown — the fixed file was the only change; CI green on e838216 (`check` 13m19s, `graph` 1m9s). Stage after the last edit, or the commit checks a different tree than the hook
- 2026-11-09, PR #44, 4a832fc: ui-quality.spec.ts equipment cases (axe landmark-unique; after that fix, the schedules table scrolled sideways at 320 px), equipment.spec.ts:125 and :154 (both 30 s timeouts) and live.spec.ts:43 (the arrival tint) — other (the new browser cases and the axe run never ran in the local check; the agent machine has no database for the browser lane) and flaky (the tint test sampled the transient 2.4 s state only after the import worker was done, which can outlast it) — the category groups are headings, not regions, so repeated category names cannot collide; the schedules and records tables become cards on a phone; the status assertions match the badge exactly; the Select is matched by its "Item" label suffix and the Dive form's save is "Save dive"; the tint test watches the tinted row from before the import commits
