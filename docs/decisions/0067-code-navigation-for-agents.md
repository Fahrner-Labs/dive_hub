# ADR 0067: Code navigation for agents

## Status
Accepted – 2026-11-07 – by the owner (plan approved on FAH-46, ADR merged in PR #34).

## Context
Agents orient themselves well at the knowledge level (`AGENTS.md` → `docs/index.md` → ADRs/glossary/spec) but have
no code-level navigation aid. Every "where is X / who calls Y / what breaks if I change Z" question is answered by
grep plus sequential file reading, which burns context window and time on every heartbeat. The repo is ~50k lines of
hand-written TypeScript across ~350 source files — large enough that this tax is real, small enough that a full
index is cheap.

A spike on `main` @ f3f1872 (2 vCPU / 3.9GB runner) compared the two serious candidates on real DiveHub symbols
(grep-verified callers of `lockManagedDive` / `participantsOfDives`, including the transitive blast radius through
`participantsOf`; full matrix in the FAH-46 research document):

- **Graphify** (`graphifyy`, MIT): deterministic tree-sitter extraction, code-only mode (zero LLM). 83s full build,
  16s incremental, **8.2MB `graph.json` that fits in git**. File-level precision; calls resolved by a corpus-wide
  name table.
- **codebase-memory-mcp** (MIT): hybrid LSP-grade type resolution — genuinely better precision (function-level
  traces, hop counts, Route/Table nodes). 30s build, but only with `CBM_MEM_BUDGET_MB=1400`, and a **289MB SQLite
  index** that cannot be committed.
- Serena: best semantics (real LSP) but GPL-3.0 and per-session language-server cold start — unfit for ephemeral
  heartbeat runners.
- dependency-cruiser: module imports only, already in devDependencies enforcing ADR 0053, emits JSON.

## Decision
Three layers, each independently useful, none blocking the others:

1. **Repo map.** A repo-owned script (`scripts/repomap.mjs`) emits `docs/generated/REPOMAP.md` — a per-module ranked
   symbol summary (~2–4k tokens), regenerated by CI on merge to `main`. Cheapest always-on orientation for any
   agent, no install.
2. **Symbol/call graph: Graphify.** CI builds the index on merge to `main` (`graphify . --code-only --no-viz
   --no-label`); `graph.json` + `GRAPH_REPORT.md` are committed under `docs/generated/` with the source SHA recorded,
   and excluded from review diffs. Agents grep/resolve the exact symbol first, then use `graphify
   explain|affected|path` with exact names — the natural-language `query` command was the weakest surface in the
   spike and is not the taught default. The graph is a hint; agents verify by reading the code (repo rule). The
   Graphify skill (`graphify install --platform kimi`) is added only through the skill-vetting rule.
3. **Module boundaries.** dependency-cruiser's existing `--output-type json` is exposed as a CI artifact, giving
   agents "what may import what" per ADR 0053 for free.

Rejected: codebase-memory-mcp as the primary graph (289MB artifact loses on runner economics; it stays the
documented deep-precision fallback for dev boxes or a future CI analysis job if the committed graph's precision
proves insufficient), Serena in runners (GPL-3.0, cold start; revisit for interactive dev machines), Graphify Cloud
(paid; single repo today), docs/ADR ingestion into the graph (docs are already well-indexed).

## Consequences
- Easier: callers-of / blast-radius / path questions answered in seconds with zero per-runner setup; module-boundary
  queries come free from dependency-cruiser.
- Harder: `docs/generated/` churns in git on every merge (mitigated: single squashed path, excluded from review
  diffs); CI and dev runners need Python ≥3.11 for Graphify; file-level precision and name-based call resolution can
  collide on cross-package aliases (codebase-memory-mcp is the mitigation); effect on token usage is measured against
  `docs/research/2026-10-07-token-usage.md` after two weeks, keep or revert per data.
